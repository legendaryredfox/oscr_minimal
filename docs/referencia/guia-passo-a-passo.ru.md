# Пошаговое руководство: от собранной платы до первого дампа

По образцу руководства `md_rewriter` (`md_rewriter/docs/guide/`). Здесь по порядку связано то, что уже есть в других документах; подробности — там. Версии: [pt-BR](guia-passo-a-passo.md), [en](guia-passo-a-passo.en.md), [zh-Hans](guia-passo-a-passo.zh-Hans.md). Перевод не проверен носителем языка.

## 0. Выберите плату и что покупать

1. Выберите плату в [`boards/README.md`](../../boards/README.md) (по системам; текущая версия каждой — в `boards/versoes.json`). **v1.0** — минимальная, с предохранителем; **v1.1** (где есть) добавляет переключатель напряжения 3,3 В/5 В.
2. Детали: `boards/<плата>/docs/bom.md` и `componentes-opcionais.md`. Детали без символа (штыри, стойки, USB-кабель) — в конце BOM.
3. Заказ платы: `boards/<плата>/fab/PEDIDO.md` (zip версии, проверка превью, SHA-256). **Проверьте разводку в KiCad до оплаты** (она сделана автотрассировщиком).

## 1. Пайка и сборка

Следуйте `boards/<плата>/docs/montagem.md`: от низких деталей к высоким (резисторы, конденсаторы, колодка PIC, светодиод, электролит, гребёнки Si5351, слоты, штыри к Mega в последнюю очередь с надетым шилдом). Затем визуальный осмотр, проверка непрерывности 5 В–GND **до включения** (замыкания быть не должно) и только потом подача питания **без картриджа, без PIC и без Si5351** с замером 5 В на VCC каждого слота.

## 2. Компьютер и прошивка

1. Linux: добавьте пользователя в группу `dialout` (`sudo usermod -aG dialout $USER`, перезайдите). В macOS и Windows драйвер Mega обычно уже есть.
2. Прошейте Mega через USB-C: `python3 host/dumper.py firmware-flash` (или карточка «Прошивка Arduino» в GUI; нужен `avrdude`). Через PlatformIO: `cd firmware/oscr && pio run -e SerialASCII -t upload` (платы с переключателем напряжения: `-e SerialASCII_Volt`).
3. `python3 host/dumper.py info` должен показать протокол, версию прошивки и системы.

## 3. Первые проверки по порядку

Подробно — в [`uso.md`](uso.md), раздел 7 (на португальском).

1. **Без картриджа:** `python3 host/dumper.py selftest` (около 45 с). Находит замыкания между выводами, подтяжку D7 и Si5351. Если что-то найдено — **остановитесь** и проверьте пайку.
2. **Режим MOCK (тестовая прошивка):** `dump -s mock` даёт CRC32 `D1DF4327`.
3. **Установите модули:** Si5351 и PIC12F629 с прошивкой `snescic-lock-resync.hex` (PIC нужен только SNES с SA-1).
4. **Mega Drive, только чтение:** `python3 tools/boards/megadrive/hwtest_md.py nocart`, затем `... cart` с картриджем в слоте. Этот набор тестов никогда ничего не пишет в картридж.
5. **Первый настоящий дамп** простого картриджа (SNES LoROM или NES mapper 0): `detect -s snes` и `dump -s snes -o igra`; сравните CRC32 с No-Intro.

## 4. Запись во флеш-репро картридж

Только после чтения и проверки. Порядок риска: сохранение с резервной копией, EEPROM, флеш GBA и в самом конце `rom-write` (стирает чип). **Никогда не пишите в оригинальный масочный картридж.** Сначала пробуйте на ненужном репро.

- Mega Drive: `rom-write -s md -i igra.md --yes`. **У картриджей KY / FlashKit с S29GL всего 2 МиБ флеша**: больше этого CLI отказывает до стирания (`--ignore-cart-limit` разрешает, если плата подключает все 8 МиБ). Прошивка проверяет `FFFFh` после стирания, а программа читает ROM обратно и сравнивает.
- Меняйте картридж **при отключённом USB** (5 В слотов программно не отключается).

## 5. Частые проблемы

Таблица в [`uso.md`](uso.md), раздел 4. Три самых частых: нет последовательного порта (группа `dialout`), картридж не определяется (почистите контакты, проверьте сторону этикетки по шелкографии) и расхождение CRC (читайте дважды: `dump --twice`).
